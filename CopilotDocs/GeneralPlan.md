# General Plan - CuSAGL-4Android

## 目标与定位
- 目标：将 `OriginScripts/CuSimpAutoGenshinLyre` 的核心能力完整移植为 Android 原生 Kotlin 逻辑，并以可维护的 Compose UI + 无障碍触控注入完成端到端演奏。
- 原则：先纯 Kotlin 核心，再 Android 绑定；核心逻辑与 UI 解耦；先对齐 JS 规则，再做结构优化。

## 当前进度摘要
- Step1：曲谱解析、缓存与预烘焙已完成（`core` 下相关模块）。
- Step2：运行时播放调度与控制接口已完成（延迟-自旋、状态机、触控接口）。
- Step3：触控注入与无障碍服务接入已完成（权限、服务生命周期、坐标映射）。
- Step4：悬浮窗控制面板的 UI 与功能（运行态播放控制、状态显示）。该步骤首先需要检查之前步骤的文档，以确保正确调用接口。需要申请悬浮窗权限。实现服务保活与运行保障。
- Step5：主页面 Compose UI （曲谱管理入口、自定义播放配置入口、预加载曲谱并保存缓存文件的功能、“准备演奏”按钮）。曲谱管理和自定义播放配置入口，只需要设计按钮和跳转，对应界面的 UI 和具体功能将在后续步骤完善。预加载曲谱并保存缓存文件的功能，需要将已实现的核心逻辑绑定到 UI 上。“准备演奏”按钮，需要根据前置步骤中核心逻辑的状态（如曲谱是否预加载完成、播放配置是否完整、无障碍服务是否已经启用）来控制其启用状态，并在点击后正确进入悬浮窗模式。
- Step6: 曲谱管理页面 UI 设计与实现（导入/删除 JSON 曲谱、手动输入曲谱）。需要展示出所有已存储的曲谱列表，提供导入和删除 JSON 曲谱的功能，并提供由用户手动输入曲谱并保存的功能。
- Step7: 播放配置界面 UI 设计与实现。需要提供原 `OriginScripts/CuSimpAutoGenshinLyre/settings.json` 中的各种自定义选项，并将这些选项正确传递给核心逻辑。

## 关键资料与规则来源
- 读谱与调度规则：`OriginScripts/CuSimpAutoGenshinLyre/README.md`。
- Android 触控映射：`README.md` 附录（1920x1080 基准坐标 + 缩放公式）。
- 代码入口与核心目录：`app/src/main/java/com/culoo/cusagl_4android/core/`。

## 总体路线（高层）
1. 核心逻辑对齐：保持解析、预烘焙、调度与缓存行为和 JS 等价。
2. Android 绑定：实现触控注入与权限管理，接入 Compose UI 控制流程。
3. 体验打磨：补充配置/管理 UI、悬浮窗控制、稳定性与性能验证。
4. 质量保障：完善单元测试与关键路径日志，保障跨设备稳定性。

## 后续分解步骤：搭建 Compose UI 与悬浮窗控制面板，完善与验证
- Step8: 杂项，UI 与功能优化，人性化设计检查。需要实现无障碍、悬浮窗权限检测，并实现引导 UI/提示流程。
- Step：配置与队列管理完善（UI->PlaybackConfig 传入与校验）。
- Step：测试与性能验证（不同分辨率与刷新率设备）。
