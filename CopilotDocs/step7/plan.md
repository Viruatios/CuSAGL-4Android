# Step7 Implementation Plan: 播放配置界面与会话配置接入

## 目标
- 实现正式播放配置页面，覆盖原 `settings.json` 的定时启动、播放模式、单曲选择、队列输入、队列间隔、循环次数、循环间隔、调试模式。
- 配置本地持久化，重启 App 后恢复。
- “准备演奏”和“预加载曲谱”使用已应用配置中的曲谱队列，而不是固定第一首曲谱。

## 范围内
1. 播放配置模型与控制器：
   - `PlaybackConfigDraft` 保存 UI 输入文本/选项和 debug 开关。
   - `PlaybackConfigController` 负责加载/保存配置、校验输入、解析队列、生成 `PlaybackSessionRequest`。
   - 使用 app 私有目录下的 JSON 配置文件持久化，不引入数据库或新导航框架。
2. 配置转换：
   - 四种播放模式映射到 `PlayType`。
   - 定时启动支持空、`HH:mm`、`HH:mm:ss`，有效值转为当天本地 epoch 毫秒。
   - 队列/循环间隔和循环次数只接受非负整数，空值默认为 0；秒数转换为毫秒。
   - debug 模式仅保留在模型和持久化中，不改变播放行为。
3. 主页面与配置页面：
   - 替换播放配置占位页。
   - 单曲模式使用单曲选择；队列模式使用队列序号输入。
   - 主页面展示已应用配置摘要和队列缓存状态。
   - 曲谱管理改动后刷新候选列表，并按 JS 规则回退失效配置。
4. 预加载与准备演奏：
   - 预加载当前已应用队列中的所有曲谱。
   - 准备演奏要求队列非空、队列内缓存全部就绪、悬浮窗权限已授予、无障碍已连接、且非加载中。

## 行为规则
- 单曲选择无效时回退排序后的第一首曲谱。
- 队列输入为空时默认全部曲谱。
- 队列序号按四位前缀精确匹配；非法、非正、无匹配序号会被忽略；重复序号去重。
- 队列输入没有任何有效匹配且存在曲谱时，回退全部曲谱。
- 非循环模式保留循环字段输入，但生成配置时不会产生循环行为。

## 范围外
- 不实现 Step8 的完整权限引导、人性化提示流程或游戏界面状态检测。
- 不让 debug 模式立即控制 `Logger` 输出。
- 不实现拖拽式队列排序、多选列表编辑器或播放历史。

## 验收
- 默认空配置且有曲谱时，生成单曲单次和第一首曲谱。
- 四种播放模式能正确传入 `PlaybackSessionRequest`。
- 定时、非负数字、队列解析、debug 持久化均有单元测试覆盖。
- 主页面使用当前配置队列进行预加载和准备演奏。
- 运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` 通过。
