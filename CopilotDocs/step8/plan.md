# Step8 Implementation Plan: 权限引导与 UI 体验打磨

## 目标
- 补齐悬浮窗权限与无障碍服务的检测、解释、跳转和返回后刷新流程。
- 在首页明确展示“准备演奏”不可用的具体原因。
- 对首页、曲谱管理页、播放配置页和悬浮窗面板做基础 UI 层级整理，不改变现有播放、曲谱、配置和服务契约。

## 范围内
1. 权限引导状态模型：
   - 根据悬浮窗权限、无障碍服务、缓存、播放请求和加载状态生成权限待办与准备演奏阻塞原因。
   - 提供纯 Kotlin 弹窗显示判断，确保首页缺权限时每轮前台生命周期只提示一次。
2. 权限跳转：
   - 悬浮窗继续跳转 `Settings.ACTION_MANAGE_OVERLAY_PERMISSION`。
   - 无障碍服务跳转系统无障碍设置。
   - Activity 返回前台后刷新权限和播放状态。
3. 首页体验：
   - 分区展示播放配置、缓存、权限待办和主要操作。
   - 准备演奏禁用时展示具体缺失项。
4. 页面基础整理：
   - 统一曲谱管理页、播放配置页的标题、消息、卡片分组和按钮层级。
   - 优化悬浮窗面板信息层级与按钮换行，避免窄宽度下挤压。

## 范围外
- 不实现游戏/演奏界面识别或自动暂停。
- 不增加数据库、Navigation Compose、ViewModel、图标库或新网络依赖。
- 不改变 `PlaybackSessionRequest`、`OverlayPlaybackService`、`RuntimePlaybackEngine` 的行为契约。
- 不让 debug 模式影响 `Logger` 输出。

## 验收
- 首次进入首页且缺权限时弹出权限说明，关闭后本轮不反复弹。
- 悬浮窗与无障碍按钮能分别进入系统设置页。
- 从设置返回后首页状态刷新。
- 准备演奏不可用时显示具体原因；权限、缓存和配置均就绪时按钮可用。
- JVM 单元测试覆盖权限待办、准备演奏阻塞原因、弹窗显示节流。
- 运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` 通过。
