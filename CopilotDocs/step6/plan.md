# Step6 Implementation Plan: 曲谱管理页面

## 目标
- 实现正式曲谱管理页面，替换 Step5 占位页。
- 支持系统文件选择器导入 JSON 曲谱、删除曲谱、表单化手动创建曲谱。
- 保存前严格校验曲谱 JSON，避免无效文件进入 `filesDir/score_file`。
- 重名判断按文件名曲名部分：`0001.曲名` 中的 `曲名`。

## 范围内
1. 曲谱列表：
   - 展示所有已存储曲谱。
   - 展示文件名、曲名、缓存状态。
   - 列表刷新时沿用 `ScoreStorage.listAndNormalizeScores` 的编号规范化规则。
2. JSON 导入：
   - 通过 Android 系统文档选择器读取 JSON 文本。
   - 校验通过后写入 app 私有目录。
   - 新曲谱使用最小可用四位编号。
   - 重名时弹确认；确认后保留旧编号覆盖文件，并删除旧缓存。
3. 手动创建：
   - 表单字段包括曲名、作者、建议乐器、描述、BPM、拍号、作曲者、编曲者、notes。
   - 保存时生成标准 JSON。
   - 与导入共享严格校验和重名覆盖规则。
4. 删除：
   - 删除曲谱文件。
   - 同步删除同名缓存。
   - 删除后刷新曲谱列表和主页面第一首曲谱/缓存状态。

## 严格校验规则
- JSON 必须合法。
- `name` 必须非空。
- `bpm` 必须是正整数。
- `time_signature` 必须形如 `N/D`，且分母为 2 的幂。
- `notes` 必须非空，且 `ScoreParser.parseNotes` 结果非空。
- 文件名曲名会去除路径分隔符和首尾空白；清理后为空则失败。

## 范围外
- 不实现 Step7 的播放配置、队列选择或多曲播放配置。
- 不实现 Step8 的完整权限引导与人性化提示流程。
- 不引入新的导航框架、数据库或持久化设置系统。
- 不把 `OriginScripts` 中的曲谱打包进应用。

## 验收
- 空目录下曲谱管理页面可正常显示空状态。
- 导入合法 JSON 后生成 `####.曲名.json`。
- 非法 JSON、缺少/空 `name`、非法 `bpm`、非法拍号、空 `notes` 均失败且不写文件。
- 手动表单保存后可被 `ScoreParser` 解析。
- 同名未确认时返回覆盖确认；确认后覆盖旧文件并删除旧缓存。
- 删除曲谱时同步删除缓存。
- 运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` 通过。
